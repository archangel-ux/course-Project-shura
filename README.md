# Qoima — Қойма есебі

**Қоймадағы тауарларды есепке алуға арналған веб-қосымша.** Браузерде ашылады, деректер мен авторизация — Supabase-те.

## Мүмкіндіктері

**Негізгі**
- Тіркелу (растаусыз, бірден кіреді), кіру, шығу, құпиясөзді email арқылы қалпына келтіру
- Тауарлар: қосу, өңдеу, мұрағатқа жіберу/қалпына келтіру, іздеу, санат және күй бойынша сүзу
- Кіріс пен шығыс; қалдық автоматты есептеледі және ешқашан теріс болмайды
- Әр тауардың қозғалыс тарихы («қалдық кейін» бағанымен)
- Басты бет: көрсеткіштер, аз қалдық тізімі, соңғы операциялар
- CSV экспорт (Excel-ге дайын: UTF-8 BOM, `;`)

**Қосымша**
1. **Жеткізушілер** — анықтамалық, кірісті жеткізушімен байланыстыру, жеткізу статистикасы
2. **Түгендеу (инвентаризация)** — нақты санды енгізу, айырма «Түзету» операциясы ретінде жазылады
3. **CSV импорт** — тауарларды файлдан жаппай жүктеу (қазақша/орысша/ағылшынша бағандар)
4. **Аналитика** — 14 күндік кіріс/шығыс графигі, ең көп шыққан тауарлар, санаттар бойынша құн, кезең таңдау (7/30/90/365 күн)

**Баптаулар**
- Тіл: қазақша / русский / English
- Тақырып: қараңғы / ашық (аккаунтта сақталады)
- Профиль: аты-жөні, ұйым, телефон; email және құпиясөзді өзгерту

## Технологиялар

- **Python 3.11+**, **Flask** — сервер және беттер (Jinja шаблондары)
- **Supabase** — PostgreSQL дерекқоры + Auth (email/құпиясөз)
- **httpx** — Supabase REST/Auth API-мен байланыс
- Таза CSS және аз ғана JavaScript (фреймворксіз)
- `unittest` — тесттер

## 1. Supabase-ті дайындау (бір рет)

1. [supabase.com](https://supabase.com) → жобаңыз → **SQL Editor** → **New query**.
2. [supabase/schema.sql](supabase/schema.sql) файлының мазмұнын қойып, **Run** басыңыз. Скрипт кестелерді (`qoima_` префиксімен), RLS саясаттарын және функцияларды жасайды. Қайта іске қосу қауіпсіз.
3. **Authentication → Sign In / Providers → Email** — **Confirm email** қосқышын өшіріңіз. Тіркелу сонда бірден аккаунтқа кіргізеді, хат жіберілмейді (скрипттегі триггер жаңа аккаунттарды да бірден растайды).
4. **Authentication → URL Configuration** (құпиясөзді қалпына келтіру сілтемелері үшін):
   - **Site URL** — сайттың мекенжайы (мысалы, `https://qoima.onrender.com`; жергілікті жұмыс үшін `http://localhost:5000`).
   - **Redirect URLs** — `https://<сайт>/auth/callback` және `http://localhost:5000/auth/callback` қосыңыз.

## 2. Жергілікті іске қосу

```powershell
cd Qoima_Project_Docs
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env          # SECRET_KEY мәнін өзгертіңіз
.\.venv\Scripts\python.exe main.py
```

Браузерде: <http://localhost:5000>

Тесттер (Supabase-сіз, жадтағы деректермен жұмыс істейді):

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

## 3. Хостинг

Қосымша кез келген Python хостингінде жұмыс істейді. Қажетті айнымалылар:

| Айнымалы | Мәні |
|---|---|
| `SUPABASE_URL` | `https://vnbpscrkqabvubtpbkwm.supabase.co` |
| `SUPABASE_PUBLISHABLE_KEY` | publishable кілт |
| `SECRET_KEY` | ұзын кездейсоқ жол |
| `SITE_URL` | сайттың нақты мекенжайы, `https://...` |
| `APP_TIMEZONE` | `Asia/Almaty` (міндетті емес) |

**Render (тегін):** кодты GitHub-қа жүктеңіз → Render → **New → Blueprint** → репозиторийді таңдаңыз. `render.yaml` бәрін өзі баптайды; тек `SITE_URL` мәнін енгізіңіз (Render берген мекенжай). Содан кейін сол мекенжайды Supabase-тегі Site URL / Redirect URLs-қа қосыңыз.

**Railway / Heroku тәрізді:** `Procfile` дайын. **Docker:** `Dockerfile` дайын (`docker build -t qoima . && docker run -p 8000:8000 --env-file .env qoima`).

## Деректер және қауіпсіздік

- Әр пайдаланушы тек өз қоймасын көреді — PostgreSQL **Row Level Security**.
- Тауар қалдығын тікелей өзгерту мүмкін емес: ол тек `qoima_register_movement` және `qoima_stocktake` функциялары арқылы, операция жазбасымен бір транзакцияда өзгереді. `quantity >= 0` шектеуі дерекқор деңгейінде.
- Бағалар `bigint` тиынмен сақталады (1 ₸ = 100 тиын), Python-да `Decimal` арқылы есептеледі.
- Publishable кілт браузерге/серверге ашық болуға арналған; қорғанысты RLS береді. **Secret/service_role кілтін** жобаға ешқашан қоспаңыз.
- Сессия — қол қойылған HttpOnly cookie; барлық формаларда CSRF токені.
- `.env` файлы git-ке қосылмайды.

```text
├── render.yaml · Procfile · Dockerfile
├── supabase/schema.sql     # кестелер, RLS, функциялар
├── app/
│   ├── __init__.py         # create_app
│   ├── config.py
│   ├── supabase_client.py  # Auth + REST HTTP клиенті

│   ├── services/           # бизнес-ережелер, валидация, аналитика, CSV

│   ├── templates/
│   └── static/             # css, js
└── tests/                  # unittest + жадтағы FakeStore
```
